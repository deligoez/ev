v0.33.0 was tagged but never published: GitHub no longer runs the macOS-14 machines its macOS
builds were set to, so they did not start. This release is v0.33.0 built on macOS 15, with the
same changes.

Small fixes from using the inventory. `ev past --to <place>` lists what went to a place
(returned to its owner, given or lent there), and `ev for` says how many did. A photo is now
either current or out of date, never both. `ev ui` draws photos with the kitty protocol
behind a multiplexer too, and its Settings tab and `ev ui --probe` say how it draws them and
why. No schema change.

## What went to a place, from the place

Things owned by another household and returned to it, things given or taken there and things
that left while lent there dropped out of `ev for <place>`, and could be found again only by
name. `ev past --to <place>` lists them as `ev past` does, with when and how each left, and
`ev for` says how many went there and how to list them.

## A photo is either current or out of date

`ev photo current` cleared an earlier out-of-date mark, but `ev photo stale` kept an earlier
"still current" one, so `ev show` printed both for one place. Marking a photo out of date now
drops the still-current mark too.

## Photos in `ev ui` behind a multiplexer

A terminal that speaks the kitty graphics protocol showed photos in `ev ui` as half blocks when
a multiplexer ran between them. `ev ui` asks four things at start and took the status report as
the last answer; the multiplexer answered the cell size and the status report itself at once
and passed the kitty and device-attribute queries on to the terminal, so `ev ui` decided before
kitty was known and kept half blocks for the whole session. It now waits for both the device
attributes and the status report, at most two seconds, and an answer that comes later still
changes the choice.

What was chosen was visible nowhere, so this could only be found by reading the code. The
Settings tab has a Pictures row: the protocol and cell size in use, why it is half blocks when
it is, and which answers came. `ev ui --probe` asks the terminal again without opening the
browser and prints every answer with the time it took to come.
